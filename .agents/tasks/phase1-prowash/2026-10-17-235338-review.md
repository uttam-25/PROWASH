# PROWASH Phase 1: Backend scaffold + mobile auth shell

Phase 1 delivers the complete Node.js/Express/MongoDB authentication API (FEAT-001) and the React Native/Expo mobile scaffold with all auth screens, navigation, and theme (FEAT-002). The backend is greenfield and ships with JWT auth, role-based middleware, password reset via hashed tokens, and a seed script for the first admin account. The mobile app bootstraps auth state from SecureStore, routes users by role, and bundles cleanly (1116 modules, exit 0). Watch for: one `CHANGES_REQUESTED` finding — hardcoded `#000` hex values in `shadowColor` properties in `CustomerNavigator.js` and `AdminHomeScreen.js` violate the "no hardcoded hex in screen/navigation files" rule; these should be moved to `colors.js`.

**Verdict**: CHANGES_REQUESTED

---

## High-level view

All 15 acceptance criteria pass with one exception. Both FEAT-001 and FEAT-002 are marked `completed`. The server package uses `"type":"module"`, ships all required dependencies, and the User model has `password: { select: false }` and `role` defaulting to `'customer'`. The `protect` middleware returns 401 on missing, expired, or malformed tokens; `requireAdmin` returns 403 for non-admin users. `authController.register` hard-codes `role: 'customer'` on every new user and explicitly rejects any body containing `role: 'admin'` with a 403 — both layers of defense are present.

The mobile token lifecycle is correct: `saveToken`/`getToken`/`removeToken` all go through `expo-secure-store`; `AsyncStorage` is reserved for non-sensitive preferences. `AuthContext` validates the stored token against `/api/auth/me` on bootstrap, and the 401 interceptor in `api.js` forces logout across all sessions.

The two `shadowColor: '#000'` values in `CustomerNavigator.js` and `AdminHomeScreen.js` are confirmed hardcoded hex strings in non-theme files, which the spec prohibits. Everything else — structure, navigation routing, `App.js` provider order, README, health endpoint — meets the criteria.

<details>
<summary>Details</summary>

### Admin role locked out of public registration

`authController.register` sets `role: 'customer'` unconditionally on the created user document and additionally returns 403 if the request body contains `role: 'admin'`. The first guard (forced assignment) is sufficient on its own; the explicit rejection is defense-in-depth and worth keeping. The only path to an admin account is `scripts/seedAdmin.js`, which runs out-of-band and reads credentials from environment variables.

### JWT auth and middleware chain

`protect` extracts the Bearer token, calls `jwt.verify`, then loads the user from the database. The `try/catch` wrapping `jwt.verify` passes `JsonWebTokenError` and `TokenExpiredError` to `errorHandler`, which maps both to 401 — so expired and tampered tokens return 401 rather than 500. `requireAdmin` is a simple role check that must follow `protect`; the route wiring in `authRoutes.js` does this correctly for the only protected route (`GET /me`).

The `protect` middleware does not check `isActive` in the database path — it does check it inline (lines 20-22 of `auth.js`), so deactivated accounts correctly get a 401. Confirmed.

### SplashScreen auth check runs after AuthContext has already resolved

`RootNavigator` renders `<LoadingView>` while `AuthContext.loading === true`. The Splash screen only enters the stack after `loading` becomes `false` and `!user` — meaning AuthContext's bootstrap has already completed and cleared the stored token before Splash renders. Splash's own `getMe()` call is therefore redundant rather than racy, but it works correctly in both success and error paths.

### Hardcoded `#000` in navigation/screen files

`CustomerNavigator.js` passes `shadowColor: '#000'` to the tab bar style. `AdminHomeScreen.js` has `shadowColor: '#000'` on two card `StyleSheet` entries. `colors.black` (`'#000000'`) already exists in the theme. These three occurrences should reference `colors.black` to stay consistent with the "no hardcoded hex in screen files" constraint. The values are correct, but the pattern breaks the rule that all color decisions live in `theme/colors.js`.

### Test coverage

No test framework was set up in Phase 1 per the context spec. The verified smoke tests (bundle export exits 0, seed script, health endpoint) all passed per FEAT-001 and FEAT-002 findings. No automated unit or integration tests cover the auth endpoints or components.
